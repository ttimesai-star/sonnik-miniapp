# SPEC: Telegram Mini App «Вещий — дневник снов» (идея №29)

Статус продукта: **prototype** (ENGINEERING_PROCESS.md). Внешних пользователей нет, отзывов нет.
Дата: 15.10.2026. Бюджет MVP: ~3 ч.

## Цель
Бесплатная страница-приложение внутри Telegram: человек записывает сон, получает толкование
из нашего словаря (178 образов RU/EN) и ведёт дневник снов с повторяющимися образами.
Назначение для бизнеса: дополнительный вход в воронку бота @sonnik_morfey_bot (там остаётся
психологический слой от модели и платные разборы). Мини-приложение само денег не берёт.

## Не входит в MVP (намеренно)
- Реальные платежи Stars: вывод Stars для РБ не проверен. Кнопка «поддержать / подписка» — заглушка.
- Психологический слой от модели: нужен сервер и ключи; здесь только словарный (классический + народный).
- Включение кнопки web_app в боте: готовится патч и инструкция, включает владелец.
- Синхронизация с дневником бота (SQLite на ПК): у Mini App своё хранилище.

## Архитектура
Статический сайт (HTML + JS + CSS, без сборщиков и зависимостей), хостинг GitHub Pages
(ttimesai-star/sonnik-miniapp, MIT). Единственный внешний скрипт — telegram-web-app.js с telegram.org.
- `engine.js` — порт `norm`, `_has_stem`, `find_symbols`, `tone`, `mood_said`, `classic`/`folk`, `recurring`
  из `projects/saas_dream/dreams.py` (JS `\b` и `\w` только ASCII, поэтому границы слов — вручную, как в Kotlin-порте).
- `app.js` — интерфейс, i18n RU/EN, тема Telegram, хранилище (CloudStorage -> localStorage).
- `dictionary/` — копия `symbols.json`, `symbols_en.json` из бота (источник правды — бот), `fixtures/` — эталон Python.

## Критерии приёмки (все проверяемые)
- AC1 Паритет движка: `node --test tests/*.test.mjs` — для всех 495 фикстур (247 RU + 248 EN) JS даёт те же образы в том же
  порядке, то же настроение, `mood_said`, список «показанных в коротком», текст пометки настроения, что Python.
- AC2 Живой паритет: `python tests/parity_live.py` прогоняет >=10 свежих текстов (не из фикстур) через
  `dreams.py` и через JS, результаты равны; `recurring()` совпадает с Python на синтетическом дневнике.
- AC3 Целостность словаря: sha256 словарей в репо = sha256 в метаданных фикстур; при наличии бота рядом = sha256 файлов бота.
- AC4 Запись сна -> толкование на клиенте, без сетевых запросов (кроме telegram-web-app.js): e2e видит 0 запросов
  на чужие домены после загрузки страницы.
- AC5 Дневник: запись сохраняется в CloudStorage (e2e с подменой Telegram.WebApp.CloudStorage видит setItem),
  без CloudStorage — в localStorage; после перезагрузки запись на месте; удаление работает; повторы за 30 дней считаются.
- AC6 Тема: цвета берутся из `themeParams` и обновляются по `themeChanged` (e2e меняет тему и сверяет CSS-переменные).
- AC7 RU/EN: переключатель меняет интерфейс и словарь толкования; язык по умолчанию — как в боте
  (ru/uk/be/kk/uz/ky -> ru, иначе en).
- AC8 Заглушка оплаты: кнопка есть, показывает честный текст «платежи не включены», в коде нет вызовов
  `openInvoice`/`createInvoiceLink`/платёжных запросов (grep-тест).
- AC9 Безопасность: пользовательский текст рендерится только через `textContent`; CSP meta;
  XSS-проверка в e2e (сон `<img src=x onerror=...>` не исполняется и показан как текст); gitleaks/grep секретов чисто.
- AC10 Страница открывается по публичному URL GitHub Pages (200), скриншот через Playwright проверен глазами,
  мобильный viewport 390x844.
- AC11 Патч для бота: `patches/bot_webapp.patch` применяется к текущему `bot.py` (`patch --dry-run`), результат
  компилируется (`py_compile`); по умолчанию без переменной `SONNIK_WEBAPP_URL` бот ведёт себя как раньше.

## Риски
- Telegram меняет `telegram-web-app.js` без версионирования, SRI невозможен: страница деградирует в браузерный режим.
- CloudStorage: ключ <=128 знаков [A-Za-z0-9_-], значение <=4096, ключей <=1024: текст сна режется до 2000 знаков, дневник до 900 записей.
- Словарь в репо — копия: после правки словаря бота нужен `tools/export_fixtures.py` (CI падает при расхождении с фикстурами).
- «Не предсказание»: в интерфейсе остаётся оговорка (как в боте); никаких обещаний будущего.
- Статус prototype: отзывов нет, продуктом не называть.

## Решения при реализации (15.10.2026)
- Толкование в Mini App = бесплатный короткий разбор бота: 3 образа + остальные по имени
  («разбираются в полном толковании») + пометка настроения, если человек писал о чувствах.
  Полный разбор (все образы, народный и психологический слой) остаётся в боте — кнопка
  «Полный разбор в боте» (`t.me/sonnik_morfey_bot?start=miniapp`, метка источника для бота).
- Настроение в дневник пишется только если человек написал о чувствах (урок 14.09: не выдумывать).
- При переключении языка уже показанное толкование остаётся на языке сна; новый сон — по словарю нового языка.
- Страница публикуется только после зелёных тестов (Pages из workflow, в сайт идут только файлы страницы).
- Фикстуры — та же выгрузка, что у Android-порта (`tools/export_fixtures.py`, sha256 совпадает байт-в-байт).
